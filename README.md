# TrendWatcher · 1.2

Новое: открытые Why Now и Recommended Actions внутри новости; подготовленные разборы без ключа; скрытое поле OpenRouter и запуск AI-анализа текущей подборки в «Источниках». Подробности: [docs/AI_ANALYSIS.md](docs/AI_ANALYSIS.md).

Рабочий прототип для продуктовых и аналитических команд банков. Новости → оценки → подробности → избранное и заметки.

Доработка проекта с сохранением Streamlit, каталога источников, словарной классификации и формулы FinSignal. Изолированы интерфейс, логика, сервисы и хранение. Исходная локальная копия использовалась для аудита без изменений; поставляется обновлённая версия проекта. Эта поставка **не обновляет автоматически** прежний сайт trendwatcheralpha.streamlit.app.

## Быстрый запуск в Windows

Установите Python 3.12. Распакуйте архив и откройте терминал в папке TrendWatcher_MVP.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run TrendWatcher.py
```

Откройте адрес, напечатанный Streamlit, обычно http://localhost:8501.

Можно также дважды нажать `start_windows.bat` — он создаст окружение, установит зависимости и запустит приложение. Требуется Python 3.12.

## macOS / Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run TrendWatcher.py
```

Тестировалось с Python 3.12 и зависимостями из requirements.txt. Пакеты закреплены на проверенных версиях, а не обозначены как самые новые.

## Новый интерфейс

Тёмная тема в красно-чёрной палитре презентации. Верхнее меню: «Новости», «Избранное», «Аналитика», «Источники». Боковой панели и отдельного «Рабочего пространства» нет.

1. В ленте видны средняя оценка, все пять критериев, источник и дата.
2. «Подробнее» открывает радарный график, подробности, ссылку и заметку.
3. «В избранное» сохраняет новость. Заметка необязательна, назначать ответственного или статус не нужно.
4. «Избранное» позволяет вернуться к сохранённым новостям, включая новости из прошлых подборок, и скачать текущую отфильтрованную подборку в Markdown или JSON.
5. «Аналитика» показывает средний профиль и распределение всех пяти факторов.
6. «Источники» → «Обновить новости» выполняет сбор и анализ одним действием. Здесь же находятся импорт, настройки анализа и история.

Фильтры по сфере, дате, поиску и средней оценке сохраняются при открытии новости и возврате. Сфера определяется по ключевым словам; одна новость может относиться к нескольким сферам. Категория события и сфера финтеха — разные признаки.

Начальная лента содержит шесть сохранённых реальных публикаций Банка России и Т-Банка со ссылками и исходными датами. Это авторские краткие изложения источников, проверенных 05.09.2026, а не результат нового сетевого сбора при каждом открытии. Список и ссылки находятся в `trendwatcher/seed.py`. Даты охватывают июль 2025 — август 2026; фильтр «Все даты» показывает всю подборку. Локальные баллы вычисляются по правилам категории. Тестовые синтетические сценарии остаются только в тестовых фикстурах и не загружаются интерфейсом.

В приложении нет служебных плашек о демонстрации. Информация о происхождении данных и методике остаётся в документации. Средняя оценка теперь является арифметическим средним пяти факторов. Взвешенный FinSignal сохранён отдельно и доступен в раскрываемом объяснении методики; фильтры и сортировка ленты используют именно среднюю оценку.

## Хранение и аккаунты

По умолчанию база находится в `data/trendwatcher.sqlite3`. Путь можно задать переменной `TRENDWATCHER_DB`. Каталог должен быть доступен на запись. Для сервера необходим постоянный диск и резервное копирование SQLite корректным способом, например через SQLite backup API.

Гостевой режим сохраняет результаты только в памяти сессии. После входа или выхода данные предыдущей сессии сбрасываются: чужие результаты в аккаунт не переносятся. Вход доступен в небольшом меню «Войти» в шапке. У вошедшего пользователя сохраняются последние 50 анализов, избранное, заметки и кэш. Сохранённые карточки не исчезают из избранного после обновления ленты. Прежние ручные отметки дайджеста читаются как избранное; старые статусы и ответственные больше не выводятся. Обычное открытие приложения не создаёт пустую запись в архиве. Пароли защищены scrypt с индивидуальной солью, вход ограничен после 5 неудачных попыток на 15 минут.

Текущие аккаунты личные. Общая организация, приглашения, роли, SSO и восстановление пароля пока отсутствуют. Для пилота с несколькими участниками можно использовать отдельные личные аккаунты и экспорт; полноценное общее пространство команды требует следующего релиза.

SQLite подходит для одной небольшой инсталляции MVP. Для коммерческого многопользовательского сервиса запланированы PostgreSQL, фоновые задания, резервное восстановление и отдельная проверка безопасности. Файловая система Streamlit Community Cloud не гарантирует сохранение локальной базы после перезапуска или пересоздания инстанса. Для постоянного пилотного архива нужен внешний диск/БД.

## Внешний ИИ: включается отдельно

**В исходном архиве были настоящие API-ключи OpenRouter и Firecrawl. Они не включены в эту поставку и не использовались при проверке. Отзовите старые ключи у провайдеров и создайте новые.** Если исходник находился в GitHub, удаление текущего файла не удаляет ключ из истории; отзыв ключа обязателен.

Без ключа всё работает в режиме локальной предварительной оценки. Для настройки собственного нового ключа:

1. Скопируйте `.streamlit/secrets.toml.example` в `.streamlit/secrets.toml`.
2. Вставьте новый ключ в `OPENROUTER_API_KEY` или задайте одноимённую переменную окружения. Не публикуйте этот файл.
3. В приложении откройте «Источники» → «Настройки анализа» и включите «ИИ-анализ».
4. Следующий запуск анализа отправит заголовки, фрагменты публикаций и контекст команды в OpenRouter и создаст оплачиваемые запросы.

По умолчанию выбрана `openai/gpt-4o-mini`; ID модели можно изменить. Модель не переключается незаметно на более дорогую. Не больше двух попыток на пакет из 6 статей; при сбое карточка явно получает метод `local`. Такие fallback-карточки не записываются в LLM-кэш. Токены успешных ответов учитываются в `stats`; это не полная биллинговая сверка неудачных запросов. Для учёта реальных расходов нужны данные провайдера.

Не загружайте внутреннюю банковскую информацию в публичный прототип. Перед пилотом подключение провайдера, состав передаваемых данных и размещение согласуются с заказчиком. В этой поставке российский LLM-провайдер не подключён; перед подключением необходимо отдельно подтвердить актуальные условия.

## Источники и импорт

В каталоге **34 записи**, это число настроенных источников, а не гарантия доступности 34 лент. Выбор источников влияет на реальный сбор. Одновременно используются до 8 потоков. Есть ограничения размера ответа, таймауты и журнал. Неудачный сбор не заменяет предыдущий набор пустыми данными.

RSS/Atom - основной метод. Дополнительный HTML-сбор извлекает только заголовки; неизвестные даты не заменяются сегодняшними. Относительные ссылки разрешаются через urljoin. Внешние переходы проверяются на публичный адрес; для промышленного размещения дополнительно ограничьте исходящий трафик инфраструктурой, в том числе против DNS rebinding.

Импорт: UTF-8 JSON-массив (или объект с `articles`) либо CSV с полями `title,text,source,url,date`. До 500 публикаций и 2 МБ; анализирует максимум 120 после фильтрации и дедупликации. Импортированные ссылки автоматически не скачиваются. Для демонстрации задайте `is_demo: true`. Экспорт карточек - результат анализа, его не следует импортировать как сырые публикации.

Пример `import_example.json` включён в архив.

## Методика

FinSignal = влияние × 30% + срочность × 25% + конкуренция × 20% + регуляторный риск × 15% + реализуемость × 10%. Каждый фактор находится в диапазоне 1–5; итоговая точность - 2 знака. Это приоритет, не вероятность и не денежный эффект.

Локальная классификация сохранена из исходного проекта и использует ключевые слова. Её качество не измерено на репрезентативной разметке. Локальная карточка получает фиксированный профиль категории без случайных надбавок. Она не придумывает штрафы, сроки или проценты потери доли.

LLM возвращает статью по ID, все пять факторов, текст и дословные выдержки. Проверка выдержек отсеивает очевидные неподтверждённые цитаты, но не доказывает правильность всего вывода. Аналитик обязан проверить факты. Авторитетность источника не включена в формулу score.

Дедупликация сравнивает каноническую ссылку, заголовок и слова. Это не embedding-based semantic search. Связанные ссылки сохраняются; они не объявляются независимым подтверждением или первоисточником автоматически.

## Проверка

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты находятся в `tests/`. Покрыты воронка, реальные cache hit, отсутствие обхода фильтра при пустом результате, даты, безопасные ссылки, ошибки score, детерминированность, сопоставление LLM по ID, неверные выдержки, RSS/Atom, постоянное хранение, изоляция аккаунтов, лимит входа и сквозной сценарий AppTest.

Проверка на 05.09.2026: все тесты прошли, HTTP healthcheck = 200. Прямые загрузки cbr.ru, Finextra и TechCrunch из среды проверки не прошли. Это не доказательство, что источники не работают у вас; актуальные адреса и сеть нужно проверить на целевом размещении. Платные API и Firecrawl не вызывались. Результат проверки нового интерфейса 1.1 записан в `CHANGELOG.md`.
